About the platform

A clinical decision support system that shows its working

IHACDP pairs validated statistical risk models with a locally-run language model. The models do the predicting; the language model does the explaining. Keeping those two jobs separate is what makes the output auditable, and is the core design principle of the platform.

◐

Why not let the LLM diagnose?

A language model left to diagnose from lab values produces fluent, confident text with no measurable error rate. A gradient-boosted classifier trained on 75,000 labelled records produces a probability with a published AUC. We use the second for the decision and the first for the narration.

◑

Observed vs. imputed

Missing inputs are filled with training-set medians so the models can still run. Every feature is tagged with its provenance, and the language model receives only the observed ones — so it cannot describe a finding that was really a placeholder.

◒

Deterministic extraction

Lab values and vitals are lifted from ordinary sentences by pattern matching with range validation, not by the language model. Numbers are never paraphrased by a neural network before reaching a classifier.

◓

Runs with the network off

Inference happens over a loopback connection to a 4-billion-parameter model on this machine. There are no API keys, no third-party endpoints, and no fallback path that would send clinical text off-device.

Data provenance

Public research datasets

All five models are trained on openly published, de-identified research datasets. No patient data from this application is ever stored or used for training.
